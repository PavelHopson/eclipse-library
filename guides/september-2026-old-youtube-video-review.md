## Что берём в проекты

### 1. GameForge / Eclipse Valhalla: vertical slice за ограниченное время

Из ролика про Unreal берём только порядок работ:

1. Сначала один измеримый core loop, управление и потеря/победа.
2. Затем минимальное окружение и читаемый feedback.
3. После этого меню, настройки, сохранение и packaged build.
4. В конце — автоматические скриншоты, короткая запись, smoke test и внешний playtest.

Готовность определяется не красивой сценой в редакторе, а запускаемым билдом и proof bundle. Движок, плагины и marketplace assets фиксируются по версиям и лицензиям.

### 2. Godogen / GameForge: отрицательный QA-кейс

Ролик про игру «только с нейросетями» превращаем в regression checklist:

- игра устанавливается на чистой машине и запускается без редактора;
- core loop понятен человеку без объяснений;
- управление, звук, пауза, выход и восстановление работают;
- нет временных assets, чужих брендов и неясных лицензий;
- производительность измерена на целевом устройстве;
- публикация требует human approval и подписанный release receipt.

Агент не может сам объявить задачу завершённой по скриншоту. Нужны исполняемый билд, тесты и человеческая приёмка.

### 3. Eclipse Creative / Media: постоянный персонаж без клонирования людей

Из FLUX/LoRA-ролика берём технологический паттерн, но не точный installation recipe:

1. Использовать только собственные, лицензированные или созданные специально изображения.
2. Запретить обучение на лице реального человека без явного согласия и цели использования.
3. Хранить dataset manifest: источник, право, согласие, hash и назначение каждого кадра.
4. Запускать обучение в изолированной локальной среде без публичного web binding.
5. Фиксировать ComfyUI, custom nodes, weights и workflow по версиям и SHA-256.
6. Проверять персонажа на разных ракурсах, эмоциях, одежде и фоне; отдельно проверять артефакты и сходство с реальными людьми.

ComfyUI остаётся актуальным, но его custom nodes являются произвольным Python-кодом. FluxGym доступен, однако не публикует стабильные releases и опирается на отдельный training stack. Поэтому Library хранит идею и ограничения, а не кнопку «установить всё».

## Почему n8n-ролики не стали карточками

n8n как платформа не устарел. Устарела форма передачи: незафиксированный JSON из Telegram, внешние сервисы, широкие OAuth-права и отсутствие threat model. Если вернуться к этим сценариям, Eclipse собирает их заново:

- production workflow хранится в приватном versioned repository;
- credentials выдаются по минимальным scopes и не попадают в экспорт;
- отправка письма, публикация и расход денег требуют human approval;
- URL, файлы и prompt input валидируются;
- есть rate limit, budget, audit log, отмена и повтор без дублей;
- сначала synthetic accounts и тестовые каналы, затем ограниченный production pilot.

## Security verdict

В рамках проверки не скачивались Telegram-шаблоны, модели, custom nodes, архивы или исполняемые файлы. В Library сохранены только YouTube-ссылки, собственный анализ и безопасные проектные выводы.

Нерешённый риск для LoRA-пилота остаётся высоким до выбора rights-cleared dataset, закреплённых версий weights/nodes и изолированного стенда. Для игровых кейсов риск средний: основной контроль — provenance assets, packaged-build QA и запрет автоматической публикации.
