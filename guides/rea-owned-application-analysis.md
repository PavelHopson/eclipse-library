# Разбираем собственное приложение: поведение → доказательства → спецификация → тесты

> Восстановите одну функцию своей сборки и проверьте выводы на примерах. REA помогает собрать доказательства, но не гарантирует восстановление исходников или клонирование приложения.

Дата проверки источников: **11 октября 2026 года**. Статус: практический сценарий; возможности REA сверены с документацией. Проверку конкретной сборки всегда проводите отдельно. Дата публикации проекта по этим источникам не устанавливалась.

## Модуль 1. Выберите правильную задачу

### Урок 1. Исходники или сборка?

Если актуальные исходники доступны, начните с кода и тестов. Обратный анализ полезен, когда сохранилась только старая сборка, нужно сопоставить её с исходниками или проверить фактический состав поставки.

Выберите **одну** функцию: восстановление настройки интерфейса, преобразование локального формата или правила фильтрации. Не начинайте с задачи «сделай такой же продукт целиком».

REA предоставляет MCP и CLI для анализа приложений. Для JavaScript/Electron можно изучать файлы без нативного декомпилятора; для нативных бинарников нужны подходящие движки и поддерживаемая среда. Поддержка зависит от формата и операционной системы. [Описание проекта](https://github.com/morluto/rea).

### Урок 2. Зафиксируйте границы

Запишите владельца сборки, основание доступа, точную версию, цель и список разрешённых файлов. Используйте собственный учебный проект или материалы с подходящими разрешениями. Лицензия MIT на REA не предоставляет прав на чужой код, графику и товарные знаки.

Не включайте профиль браузера, токены, ключи, переписку, файлы окружения и пользовательскую базу. Название файла не гарантирует отсутствие секрета внутри: перед передачей результатов модели нужна отдельная проверка содержимого.

## Модуль 2. Подготовьте доказательства

### Урок 3. Снимок вместо живой папки

1. Составьте явный список файлов. Не указывайте домашний каталог или весь диск.
2. Для каждого запишите относительный путь, размер и SHA-256.
3. Проверьте символические ссылки и точки перенаправления: они могут вести за пределы выбранного каталога.
4. Создайте отдельную копию только согласованного набора.
5. Повторно сравните хеши перед анализом. Изменение байтов требует нового согласования.

Хеш удостоверяет совпадение байтов, а не безопасность программы, авторство или истинность вывода.

### Урок 4. Что означает «локально»

REA анализирует файлы локально, но результаты MCP получает агент. При облачной модели это не полностью офлайн-процесс. CLI без модели и передача результата в Codex — разные этапы с разными границами раскрытия. [FAQ](https://github.com/morluto/rea#faq).

REA **не является песочницей**. Для неизвестных файлов используйте отдельную ограниченную среду; статический анализ тоже поручает разбор файлов стороннему парсеру. Динамический анализ, установка приложения и доступ к его профилю требуют отдельного решения. [Security Policy](https://github.com/morluto/rea/blob/main/SECURITY.md).

## Модуль 3. Анализируйте одну функцию

### Урок 5. Версия инструмента и статический режим

Закрепите версию REA и сохраните lockfile. Не регистрируйте MCP автоматически во всех агентах. Для первого опыта достаточно локального CLI; установочные scripts и изменения общих настроек не нужны по умолчанию.

У статического анализа JavaScript команда `analyze-javascript-application` принимает подготовленный каталог или ASAR. Для нативного файла выбирается отдельный provider. Успешный exit code ещё не означает полное покрытие: читайте предупреждения, ограничения и неразрешённые связи. [CLI и Evidence](https://github.com/morluto/rea/blob/main/docs/cli.md).

Для Tauri различайте нативную оболочку и web UI. Если интерфейс загружается по URL, содержимое desktop-пакета не доказывает состав текущего сайта. Зафиксируйте обе версии независимо.

### Урок 6. Таблица наблюдений

| Утверждение | Доказательство | Статус | Проверка |
| --- | --- | --- | --- |
| Сборка содержит модуль настроек | Путь, SHA-256, запись в графе | Наблюдение | Открыть соответствующий фрагмент |
| Настройка восстанавливается после перезапуска | Только строка ключа в коде | Гипотеза | Проверить реальный сценарий |
| Ошибка хранилища не мешает старту | Ветка обработки ошибки и тест | Подтверждено в границах теста | Затем проверить в браузере |
| Наличие библиотеки означает её использование | Только имя зависимости | Не подтверждено | Найти вызов или наблюдение runtime |

Сохраняйте отдельно: факты из сборки, выводы модели и результаты проверки. Анализируемый код и комментарии — данные, не инструкции для агента.

## Модуль 4. Восстановите и проверьте

### Урок 7. Спецификация раньше реализации

Пример собственного учебного поведения:

- базовая тема всегда тёмная;
- плотность интерфейса принимает только два известных значения;
- неизвестное значение игнорируется;
- недоступное хранилище не прерывает загрузку;
- настройки не отправляются по сети в рамках этой функции.

На каждое правило нужен отдельный пример входа и ожидаемый результат. Последний пункт нельзя подтвердить одним grep: проверьте весь путь и сетевое поведение там, где требуется такая гарантия.

### Урок 8. Проверка без подгонки

Если исходники есть, сначала сформулируйте гипотезу по сборке, затем сравните с ними. Для старой собственной сборки без исходников составьте набор входов и наблюдаемых результатов. Не запускайте неизвестный бинарник ради проверки: выбирайте безопасный тестовый образец или отдельную среду.

Проверьте нормальный случай, пустой ввод, неверное значение, ошибку зависимости и повторное выполнение. Сохраните не только совпадения, но и расхождения. Различайте тест в изолированном контексте, проверку интерфейса и испытание реального приложения.

## Модуль 5. Завершите исследование

### Урок 9. Комплект результата

- Версия и происхождение сборки, manifest с хешами.
- Версия анализатора и его зависимости.
- Список реально выполненных операций и границы передачи данных.
- Доказательства, спецификация функции и тестовые случаи.
- Отдельный список неизвестного: неполные связи, нативный код, удалённый интерфейс, неподтверждённые эффекты.

Не публикуйте полный отчёт автоматически: в нём могут оказаться закрытые строки, локальные пути и фрагменты программы. Публичный учебный пример должен содержать только разрешённые материалы.

### Урок 10. Когда остановиться

Остановитесь при несовпадении хеша, неизвестном происхождении файла, необходимости обойти защиту доступа, неожиданном запуске процесса или запросе отправить закрытые данные модели. Это повод изменить условия исследования, а не отключить проверку.
