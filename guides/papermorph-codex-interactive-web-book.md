# Papermorph-подход: интерактивная веб-книга из PDF в Codex

> Практический гайд для Eclipse Media: как превратить разрешённый PDF в проверяемый storyboard веб-книги, а затем отдельно подключить озвучку, анимацию и квизы.

Статус: пилотный workflow. На 18 октября 2026 года проверены README и skill Papermorph; локальный Media-пилот создаёт только metadata-manifest и редактируемый storyboard. PDF не отправляется провайдерам автоматически.

## Модуль 1. Граница задачи

### Урок 1. Что именно берём из Papermorph

Papermorph предлагает последовательность `PDF → style → storyboard → narration → animation & quizzes → web book`. В Eclipse Media она разделена на отдельные подтверждаемые этапы: источник и права, структура глав, beats, озвучка, анимация и экспорт.

Источник: [DozenTwelve/Papermorph](https://github.com/DozenTwelve/Papermorph), [Papermorph skill](https://raw.githubusercontent.com/DozenTwelve/Papermorph/main/.claude/skills/papermorph/SKILL.md). Это архитектурный reference; установка Claude Code не требуется.

### Урок 2. Что не обещаем

Первый пилот не утверждает, что текст PDF уже извлечён, озвучен или превращён в готовый курс. Не создавайте публичный материал, пока редактор не проверил цитаты, изображения, лицензии и ответы квиза.

## Модуль 2. Подготовка источника

### Урок 1. Паспорт PDF

Перед импортом запишите название, владельца, дату получения, размер, SHA-256 и основание права на обработку. В открытый manifest попадает только metadata и хэш; сам PDF остаётся в приватном рабочем каталоге.

### Урок 2. Сценарий без скрытой отправки

В интерфейсе должны быть видны локальный режим, подтверждение прав и этап, на котором находится материал. Внешний provider не вызывается при выборе файла или сборке storyboard. Любую передачу текста, изображений или аудио согласуйте отдельно.

## Модуль 3. Storyboard и книга

### Урок 1. Структура главы

Начните с четырёх beats: контекст, главная идея, практика и итог. Для каждого сохраните короткую narration, визуальную задачу, длительность и при необходимости один вопрос с вариантами ответа. Каждое утверждение должно иметь страницу или другой проверяемый источник.

### Урок 2. Визуальная система

Зафиксируйте mood, palette, typography и voice в `style` до подготовки SVG-сцен. Для стандартного web-book используйте stage 1600×900, крупную типографику, читаемые подписи и keyboard-friendly controls. Не прячьте смысл в анимации.

## Модуль 4. Приёмка и экспорт

### Урок 1. Локальная приёмка

Проверьте: source hash, статус прав, порядок beats, длительности, видимость captions, правильный ответ квиза, reduced-motion и работу на узком экране. Ошибка импорта не должна стирать предыдущий план.

### Урок 2. Что экспортировать

Для продолжения работы экспортируйте JSON manifest. Он должен явно показывать `narration: not-generated`, `animation: not-generated` и `quizzes: editable-draft`, пока соответствующие этапы не прошли ручную проверку. MP4 и SRT добавляйте только после отдельной проверки таймлайна и прав на звук.

## Порядок расширения

1. Подключить локальное извлечение текста с привязкой к страницам.
2. Добавить ручной редактор chapter/beat и сохранение версий.
3. Подключить выбранный TTS только после подтверждения текста, голоса, стоимости и retention.
4. Добавить SVG-рендер и экспорт MP4/SRT.
5. Включить публикацию только после accessibility, security и rights review.

До выполнения этих шагов карточка остаётся пилотной. Красивый preview не заменяет проверку источников и разрешений.
