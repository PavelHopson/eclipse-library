# Point‑cloud hero: художественный портрет на WebGL без «чёрного экрана»

> Руководство по одноэкранному арт‑дирекционному hero с облаком точек, дымом и светом — с безопасной загрузкой, fallback и измеримым GPU‑бюджетом.

Дата адаптации: **23.08.2026**
Источник идеи: пользовательский PDF `free.pdf`.
Статус: **архитектура и prompt contract созданы заново; бинарные ассеты исходника не распространяются**.

## Короткий вывод

Облако точек из десятков тысяч частиц хорошо работает как портфолио‑демо, интро к выставке или
арт‑дирекционный кейс. Оно плохо подходит для формы, кабинета или страницы, где пользователь должен быстро
совершить действие. Исходный промпт подробно описывает raw WebGL и шейдеры, но привязан к сторонним
`points.bin` и фиксированному визуальному результату.

Адаптация Eclipse строится вокруг собственного point‑cloud asset, worker‑декодирования, одного render loop,
статичного poster fallback и честной прогресс‑индикации.

## Модуль 1. Выбор формата

### Урок 1. Когда one‑viewport оправдан

Подходит:

- обложке интерактивного портфолио;
- цифровой выставке или музыкальному релизу;
- отдельному эксперименту Motion Lab;
- короткой презентации технологии частиц.

Не подходит основному экрану CRM, AI‑офиса, магазина или документации. Там визуальный слой может жить в
малой демонстрационной области, не занимая весь viewport.

### Урок 2. Композиция до шейдеров

Сначала соберите статичный кадр: объект читается в центре, заголовок не спорит с лицом, навигация видна на
светлых и тёмных участках, CTA доступны без движения. Только после одобрения poster добавляйте:

1. сборку точек;
2. медленное поверхностное движение;
3. локальную реакцию на указатель;
4. дым и лучи;
5. редкие эмберы.

## Модуль 2. Свой point‑cloud asset

### Урок 1. Pipeline данных

Исходный mesh или depth capture должен принадлежать проекту либо иметь разрешённую лицензию. Экспортируйте
позиции, нормали и при необходимости цвет в версионированный бинарный формат. Рядом храните manifest:

```json
{
  "schemaVersion": 1,
  "pointCount": 48000,
  "attributes": ["position", "normal"],
  "componentType": "float32",
  "bounds": { "radius": 1.2 },
  "sha256": "...",
  "license": "project-owned"
}
```

Проверьте длину буфера до создания typed array. Не доверяйте manifest из сети без схемы, ограничений и
хэша.

### Урок 2. Загрузка без ложного прогресса

Прогресс строится по реальным этапам: HTML/CSS готовы, poster декодирован, бинарный файл получен, буфер
проверен, shader скомпилирован. Таймер 0→100, не связанный с работой, создаёт зависание на 99% и скрывает
ошибки.

Если один этап падает, curtain убирается и остаётся poster с текстом. Никогда не оставляйте пользователя на
пустом экране.

## Модуль 3. Рендер и свет

### Урок 1. Один цикл и минимум проходов

Для raw WebGL достаточно трёх слоёв:

- полноэкранный фон: градиент, domain‑warped noise и ограниченные лучи;
- `POINTS`: форма и интерактивное освещение;
- небольшое поле эмберов.

Дублировать все точки ради плотности можно только после замера. Сначала увеличьте perceptual density через
размер, alpha gate и освещение. На мобильном уменьшайте point count заранее, а не только DPR.

### Урок 2. Читаемая форма

Нормаль и направление на камеру дают базовую яркость. Тёмная сторона не должна превращаться в серую массу
из‑за additive blending. Ограничьте alpha слабых точек и используйте мягкий круглый sprite. Cursor‑burst
меняет небольшой радиус, а не разбрасывает всю модель.

Параметры хранятся в конфигурации с безопасными диапазонами. Shader compile errors остаются включены в
development.

## Модуль 4. Производительность

### Урок 1. Три профиля качества

| Профиль | Точки | DPR | FPS цель | Фон |
|---|---:|---:|---:|---|
| high | 45–60k | до 1.5 | 60 | полный noise + rays |
| balanced | 24–36k | до 1.2 | 45 | меньше octaves |
| safe | poster | 1 | без цикла | CSS‑градиент |

Автовыбор учитывает размер экрана, `prefers-reduced-motion`, `saveData`, hardwareConcurrency и результат
короткого warm‑up. Пользователь может вручную отключить эффект.

### Урок 2. Жизненный цикл

- один `requestAnimationFrame`, отменяемый при destroy;
- `visibilitychange` ставит сцену на паузу;
- resize обновляет CSS размер и drawing buffer по debounce;
- все buffer/program/texture удаляются;
- network timeout переводит в poster;
- контекст `webglcontextlost` обрабатывается без бесконечной перезагрузки.

## Модуль 5. Доступность и управление

### Урок 1. Canvas не является содержанием

Видимые слова существуют в семантическом HTML. Canvas получает краткое текстовое описание или остаётся
декоративным. Навигация и кнопки доступны с клавиатуры; контраст проверяется поверх самого светлого кадра.

Режим reduced motion показывает статичную композицию без сборки частиц, дрейфа, вспышек и параллакса.
Официальное поведение медиа‑запроса описано в
[MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion).

### Урок 2. Pointer и touch

Используйте Pointer Events и нормализованные координаты. На touch эффект реакции включается только после
касания canvas и не блокирует системные жесты. Fallback не требует «водить мышкой, чтобы увидеть страницу».

## Модуль 6. Контракт для coding‑агента

### Урок 1. Адаптированный запрос

```text
Создай one‑viewport арт‑дирекционный hero с point‑cloud объектом.
Используй только приложенный owned asset и его manifest; не загружай файлы
из референса. Сначала реализуй статичный poster и весь HTML‑интерфейс.

Затем добавь один WebGL render loop: procedural background, points и редкие
embers. Реальный loader отражает этапы fetch/validate/compile и всегда выходит
в poster fallback при ошибке.

Нужны quality profiles, DPR/FPS budget, pause on hidden, context-loss handling,
dispose, pointer/touch, keyboard, reduced motion, save-data и responsive QA.
Не копируй точные shader constants из исходного референса: подбери параметры
по нашему approved poster и зафиксируй их в CONFIG.
```

### Урок 2. Проверка

- объект узнаваем на poster и в движении;
- сеть offline, 404 или повреждённый binary не дают чёрный экран;
- на мобильном нет перегрева и случайного zoom/scroll lock;
- после 30 переходов между страницами GPU memory не растёт;
- reduced motion не запускает rAF;
- контент и CTA доступны без WebGL.

## Модуль 7. Применение в Eclipse

### Урок 1. Лучшие места

- **Eclipse Motion Lab** — эталон генеративного point‑cloud компонента;
- **Eclipse Forge Landing** — только отдельный кейс с poster‑превью;
- **Eclipse Library** — manifest contract и performance checklist;
- **Sentinel Presence** — очень лёгкий ambient‑фон, но не лицо/биометрия пользователя без согласия.

### Урок 2. Не превращать стиль в шаблон

Не используйте point cloud, дым, огромную типографику и full‑screen preloader одновременно на каждом сайте.
Один проект — один главный визуальный жест. В рабочих интерфейсах эффект должен уступать данным и действиям.
