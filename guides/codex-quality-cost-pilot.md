# Экономия лимитов Codex без потери качества

> Практический протокол: ограничить контекст, разделить работу по сложности и сравнить качество с полным расходом. Без обещаний «в два раза дешевле» и без автоматической покупки API.

Статус: методика и локальный инструмент сравнения. Экономия на реальных моделях пока не измерена. Дата проверки документации: 18 октября 2026 года.

## С чего начать

Выберите одну повторяющуюся задачу. Для примера — определить формат публичного материала: гайд, инструмент, новость или ручная проверка. Это не проверка фактов, лицензий или разрешение на публикацию.

Не устанавливайте новый оркестратор ради первого теста. Используйте привычный Codex. Механические операции выполняйте скриптами, а не моделью. Дайте конкретные файлы, цель, ограничения и критерии готовности; не запрещайте читать связанные зависимости, необходимые для правильного решения.

Для передачи между этапами сохраните краткое резюме решений, файлов, выполненных проверок и следующего шага. Старый отчёт не выдаёт новые разрешения. Самопроверка модели не заменяет тесты и проверку пользовательского сценария.

## Одна выборка, два режима

[Открыть сравнение в Decision Lab](https://library.eclipse-forge.ru/experiments/decision-lab/compare.html). При локальной подготовке страница находится рядом с index.html пилота: compare.html. Ссылка production становится доступной после отдельной публикации.

1. Соберите разрешённые публичные материалы. Разметьте их без подсказок модели; второй редактор проверяет эталон. Источники, переводы и пересказы не должны пересекаться с данными разработки и настройки.
2. В [разметке Decision Lab](https://library.eclipse-forge.ru/experiments/decision-lab/index.html#advanced) используйте выборку «Тест», затем скачайте JSON. Семь встроенных примеров с подсказками не подходят. Не удаляйте поля происхождения, чтобы обойти ограничение.
3. Импортируйте JSON в сравнение и зафиксируйте набор. SHA-256 связывает результаты с конкретными текстами, эталоном и версией методики. Это обнаружение несовпадения, не подпись и не доказательство независимого редактора.
4. Скачайте задания А и Б и шаблоны ответов. В заданиях только описания и ID: эталонные категории, объяснения и группы не передаются.
5. Выполните А одной сильной моделью в чистом контексте. Выполните Б в другом: простая размечает всё, сильная проверяет неоднозначные ответы и каждый пятый материал из заранее зафиксированного списка. Этот систематический контроль воспроизводим, но не является случайной репрезентативной выборкой.
6. Импортируйте результаты. При повторе после просмотра ошибок используйте новый независимый набор; не выдавайте подгонку по тесту за улучшение качества.

Ориентир первого пилота — не менее 50 материалов, 10 групп источников и 5 примеров каждой из четырёх категорий. Это выбранные инженерные пороги, не статистическое доказательство. Меньший набор позволяет проверить механику, но не принять модель.

## Что записывать в результат

Шаблон JSON содержит mode, benchmarkId и policy. Все ID должны присутствовать ровно один раз. predictions сохраняются после модельной обработки, **до ручных исправлений**. В каскаде сохраняются initialRoute, initialNeedsReview и checkedByStrong.

В stages перечисляйте все вызовы — включая координатора, проверки и повторы. Для каждого этапа: точный provider/model, billing (subscription, api или local), calls, inputTokens, cachedInputTokens, outputTokens и costUsd. Кэшированные токены входят во входные; не складывайте их повторно. Неизвестное измерение — null, а не ноль. Стоимость подписки или локального запуска не подменяется API-долларами: costUsd для них null.

elapsedMs — полное время выполнения, humanReviewMinutes — время редактора, humanCorrections — число исправленных материалов. allCallsIncluded означает декларацию полноты учёта, completedAt — время завершения ISO. Сайт проверяет структуру и согласованность, но не получает квитанции от провайдера и не удостоверяет личность оператора.

Сравнение показывает совпадение с эталоном, полноту по каждой категории, ошибки без флага проверки, ручную нагрузку, время и расход. Процент денежной экономии вычисляется только для полностью API-оплаченных прогонов с известными расходами и ненулевой базой. Снижение токенов разных моделей само по себе не доказывает экономию денег или лимитов.

Кандидат на повторный пилот не должен ухудшать точность, полноту категорий, пропущенные ошибки и ручную нагрузку. Даже выполнение этих условий на одном наборе не является допуском в production. Время выполнения оценивайте отдельно под свой сценарий.

## Безопасность и сохранение

Страница не делает внешних запросов, не вызывает модели, не принимает API-ключи и не меняет сохранения старого Decision Lab. Состояние сравнения находится в памяти вкладки. Скачайте пакет для продолжения; он содержит эталон и не предназначен для исполнителей, публикации или отправки провайдеру. Загрузка пакета проверяет контрольную сумму и результаты.

Конкретный внешний провайдер, передаваемые данные и платный бюджет согласуются отдельно. Материалы — входные данные, не инструкции для агента; ссылки из них не следует автоматически открывать, а код — запускать. Ответ модели не разрешает публикацию, обучение или действия с аккаунтами.

## Что подтверждено источниками

- [OpenAI: Pricing](https://learn.chatgpt.com/docs/pricing): включённые лимиты, дополнительные кредиты и API-оплата различаются. Цена кредита сама по себе не определяет объём подписки.
- [OpenAI: Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents): отдельные роли могут менять модель и инструкции, но наследуют провайдера и разрешения. Указание стороннего имени модели в TOML само по себе не подключает новый API.
- [Исходный разбор Web3nity](https://www.youtube.com/watch?v=FmqsySNaH-E): разделение работы, ограничение контекста и сравнение на одинаковой задаче. Численные обещания экономии не использованы как доказанный результат нашего пилота.

Настройка ролей полезна, когда задачи независимы и есть измеримый выигрыш. Для небольшой последовательной задачи один агент часто проще. Покупка новых подписок, установка ORCA или переход на Claude Code для этой методики не требуются.
