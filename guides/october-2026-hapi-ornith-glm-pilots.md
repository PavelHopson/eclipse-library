## Модуль 1. Что действительно известно

### Урок 1. HAPI: телефон управляет компьютером

[HAPI](https://hapi.run/) связывает агентский CLI, собственный Hub и мобильный/веб-клиент. Сессия продолжает выполняться на рабочей машине. Через Web/PWA доступны diff, запросы разрешений и терминал; Telegram — ещё один интерфейс. Возможности нативных приложений отличаются от Web. [Архитектура](https://hapi.run/docs/guide/how-it-works).

Для Eclipse используем только Codex. Документация подтверждает его интеграцию, но не автоматический перенос всех существующих чатов Codex Desktop. Проверять нужно новую изолированную сессию, не подключать сразу всю историю. [Матрица агентов](https://hapi.run/docs/guide/agents).

Hub хранит сообщения и является доверенной частью системы. Удалённый доступ — не просто просмотр: компрометация токена может дать доступ к агенту и терминалу. Предлагаемый старт: private network + HTTPS, минимум прав, без yolo, без ключей production. [Развёртывание](https://hapi.run/docs/guide/deployment).

Голосовой помощник — отдельный провайдер и передача контекста; он не становится локальным от размещения Hub на своём ПК. Сначала диктовка с просмотром текста, затем отдельная оценка голосового режима. [Голос и диктовка](https://hapi.run/docs/guide/voice-assistant).

### Урок 2. Ornith: размер файла не равен потреблению памяти

[Ornith 1.5 9B GGUF](https://huggingface.co/ornith-ai/Ornith-1.5-9B-GGUF) — отдельная 9B-модель. В таблице издателя SWE-bench Verified: 70,6 против 73,4 у Qwen3.6-35B-A3B; универсального превосходства нет. Результаты автора не являются нашим независимым benchmark.

Q4_K_M занимает около 5,78 ГБ; отдельно опубликован mmproj около 922 МБ. KV-cache, runtime и ОС требуют дополнительной памяти. Text-generation tag не доказывает отсутствие визуальных возможностей, но mmproj сам по себе не подтверждает совместимость выбранного runtime. Заявленный контекст 262 144 не означает комфортную работу на любом телефоне. [Файлы](https://huggingface.co/ornith-ai/Ornith-1.5-9B-GGUF/tree/main).

Self-improving относится к обучению у издателя, не к самопроизвольному обучению скачанного файла. [Описание обучения](https://ornith.ai/ornith_1_5.html).

### Урок 3. Ox Alpha: раскрытое имя и изменившиеся условия

[Страница Ox Alpha](https://openrouter.ai/stealth/ox-alpha) раскрывает модель как Z.AI GLM-5.3-Flash. Preview-страница сообщает о сохранении запросов и ответов без использования для обучения: это не обещание нулевого хранения. Рекламное превосходство «20–30%» не подтверждено проверенными источниками.

[Текущий маршрут GLM-5.3-Flash](https://openrouter.ai/z-ai/glm-5.3-flash) имеет платные тарифы, зависящие от провайдера. Перед вызовом заново проверить цену, retention и endpoint. Не принимать старую акцию за действующий бюджет. Существующая карточка Library: `zai-glm-5-3-flash`; `openrouter-ox-alpha` сохраняется как историческая ссылка, без новой дублирующей модели.

## Модуль 2. Как применить в Eclipse

### Урок 4. HAPI — мобильный контроль одной задачи

Предлагаемый сценарий: открыть на ПК тестовую задачу Library → с телефона прочитать результат → отклонить пробное действие → разрешить ограниченное изменение → проверить diff → вернуться на ПК с тем же контекстом.

Первый этап подготовки: закрепить версию, проверить источник и лицензию, выбрать изолированное окружение, описать выдачу/отзыв доступа и отключение сервиса. Не считать поддержку CLI доказательством совместимости с текущим Windows и установленным Codex.

Приёмка пилота: не менее трёх повторов; отказ не выполняет действие; reconnect не повторяет изменение; отмена действительно останавливает работу; отзыв токена блокирует доступ. Начинать с read-only, затем тестовая папка без production secrets. Не превращать телефон в безусловную кнопку deploy. Голос, Telegram, public relay и постоянный автозапуск не входят в первый этап.

### Урок 5. Ornith — локальный помощник для материалов

Кандидат для Library: теги, выжимки, структурированный JSON. Для Media: готовая расшифровка → план сцен с привязкой к исходному тексту. Для AI Hub / Sentinel: локальный маршрут без передачи документов облаку, после проверки сетевого поведения runtime.

Предлагаемый набор: 20 синтетических или открытых русскоязычных задач — 8 выжимок с проверяемыми фактами, 6 JSON-извлечений, 6 планов сцен. Одинаковые входы и рубрика для текущей одобренной модели и кандидата. Начать с контекста 8k, затем 16k; записать устройство, память, runtime, ревизию, квантование, SHA-256, задержку первого токена, tok/s, пиковую память, ошибки и выдуманные факты.

До запуска согласовать устройство и объём загрузки. Критерии качества и лимиты памяти/времени зафиксировать до измерений; не подгонять их под результат. Телефон — отдельный этап после ПК. Никакого автоматического применения сгенерированного кода.

### Урок 6. GLM-5.3-Flash — ограниченное сравнение провайдера

Использовать ту же рубрику на открытых данных. Подготовить конфигурационный пример без ключей, оценку верхнего бюджета, timeout/cancel и обработку ошибок. Не включать автоматический fallback, способный незаметно отправить локальные данные в облако.

До реального API-вызова нужны выбранные endpoint/provider, правила обработки данных и бюджет пользователя. После теста отдельно оценить качество, стоимость и задержку. Большой контекст — не доказательство точности извлечения и не причина отправлять весь репозиторий.

## Модуль 3. Границы подготовки и внедрения

### Урок 7. Сначала подготовка, затем подтверждённый пилот

На этапе подготовки можно описать архитектуру, fixtures, рубрику, конфигурации-заглушки и тесты без внешних вызовов. Установка удалённого управления, открытие сетевого доступа, загрузка модели, облачные расходы и production требуют отдельного согласования конкретной операции. Codex остаётся инструментом разработки; Claude Code не устанавливать.

Не создавать второй Gateway или новый общий реестр: перед реализацией сверить существующие AI Hub / Sentinel / ULTRON контракты и владельцев. HAPI управляет сессиями, модель отвечает на запросы, Gateway маршрутизирует вызовы — это разные роли.
