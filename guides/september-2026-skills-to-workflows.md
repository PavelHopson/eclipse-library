# Из новостей в рабочие инструменты: зацепки, проверка ТЗ и маркетинговые эксперименты

> Практический разбор подборки 10–11 сентября 2026: что применено в Eclipse Media и AI Hub, какие подключения требуют отдельного допуска и чему нельзя доверять автоматически.

Проверка первичных страниц: 11 сентября 2026. Статус реализации: **локальная версия, не production**. Ни наличие ссылки, ни открытый исходный код, ни установка skill не означают безопасное подключение аккаунта. Используем Codex; конфигурация Claude Code не активируется.

## Модуль 1. Первые три секунды ролика

### Урок 1. Три согласованных слоя

В [Content Skills](https://github.com/vyralcontent/content-skills) полезна конструкция visual + verbal + on-screen text. Мы применили её как собственный локальный редактор, без установки пакета и отправки сценариев наружу.

В Eclipse Media откройте «Сценарий проекта» → «Первые 3 секунды ролика». Укажите тему, аудиторию, задачу и результат, который действительно покажете. Кнопка подготовит шесть заготовок: по две демонстрации, постановки проблемы и вопроса. Это детерминированные шаблоны, а не результат работы модели и не обещание вирусности.

Выберите вариант, отредактируйте кадр, реплику и надпись. Прочитайте реплику вслух: три секунды — плановая длительность сцены, а не измерение синтеза речи. Предупреждение о девяти словах — ориентир, не универсальная норма.

### Урок 2. Обещание и продолжение

Пример: тема — библиотека анимаций; проблема — долго искать подходящий эффект; результат — найти пример через фильтр. В начале покажите реальный найденный эффект, затем сам поиск. Не обещайте рост продаж, экономию времени или численные результаты без подтверждения.

После подтверждения «Обещание соответствует ролику» зацепка добавляется **новой первой сценой на 3 секунды**. Старые сцены сохраняются. Изменение реплики снимает подтверждение. Отмена удаляет только добавленную неизменённую сцену; ручные правки не стираются. Сцена использует существующее автосохранение и экспорт проекта Media. Заготовки до вставки не сохраняются между открытиями раздела.

## Модуль 2. Проверка ТЗ до реализации

### Урок 3. Шесть вопросов вместо бесконечного интервью

[Matt Pocock Skills](https://github.com/mattpocock/skills) / идея Grill Me полезны как способ выявлять неясности. В AI Hub → Spec Gate добавлена собственная проверка по правилам: пользователь, измеримый результат, ошибка и восстановление, границы, доступ к данным, откат. При упоминании платежей появляется вопрос о повторном списании и возврате.

Сначала опишите проблему, затем откройте «Найти пробелы в ТЗ». Дайте шесть коротких однострочных ответов. Они добавляются в существующие «Уточнения». Если ТЗ изменилось, вопросы нужно обновить. Ранее введённый другой ответ не заменяется молча. Максимум десять уточнений в итоговом контракте сохраняется.

### Урок 4. Ответы не являются разрешением

Дальше действует прежний процесс Spec Gate: спецификация → review → готовность → подтверждение. Это не снимает отдельный запрет на автоматическую реализацию, deploy, аккаунты и расходы. Проверка по ключевым словам может пропускать риски; она помогает ревьюеру, а не заменяет инженерный аудит.

Проверяемость: исходное уточнение остаётся в документе, новые ответы видны, повторное добавление не плодит дубли, JSON не получает разрешений на исполнение.

## Модуль 3. Маркетинг без скрытого запуска рекламы

### Урок 5. Что считаем

В [NotFair](https://github.com/nowork-studio/notfair-plugin) интересен набор маркетинговых проверок. Однако весь пакет включает внешнюю инфраструктуру и подключение рекламных сервисов. Вместо автоматической установки в Growth OS добавлен локальный «Проверить рекламный эксперимент».

Введите название, происхождение данных и окно атрибуции, одну валюту и два непересекающихся периода одинаковой длительности. Для каждого: расход, клики, уникальные лиды после клика, выручка. Ноль вводится явно; пустая строка не считается нулём. Это узкая модель атрибуции: один уникальный лид на клик; для view-through и нескольких целей сначала нормализуйте отчёт.

Формулы: CPA = расход / лиды; ROAS = выручка / расход; конверсия = лиды / клики × 100%. При нулевом знаменателе показатель не определён. Выручка не равна прибыли; налоги, себестоимость и возвраты автоматически не учитываются.

### Урок 6. Что не заключаем

Сравнение CPA появляется только после подтверждения одинаковой цели и атрибуции. Меньше 30 лидов вызывает предупреждение, но этот порог **не доказывает** статистическую значимость. Разница показателей не устанавливает причинность и победителя теста.

Отчёт содержит вопросы для следующей проверки и JSON с выключенными разрешениями на доступ к аккаунтам, публикацию, запуск рекламы и изменение бюджета. Любое изменение ввода убирает старый результат. Ввод хранится только в памяти открытого раздела; скачайте отчёт, если хотите его сохранить. Не вставляйте клиентские списки, токены и персональные данные.

## Модуль 4. Подключения: сначала права, потом установка

### Урок 7. Avito, Instagram, amoCRM, Telegram

| Материал | Что выяснили | Применение и условие допуска |
| --- | --- | --- |
| [Avito MCP](https://github.com/elchin92/avito-mcp) | Сторонний сервер для Avito API; конфигурация по умолчанию использует full_access. | Сначала конкретный аккаунт и разрешённый API. Отдельный read_only профиль и список разрешённых методов. Подтверждение внутри MCP само по себе не доказывает участие человека. |
| [Instagram MCP](https://github.com/adelaidasofia/instagram-mcp) | Сторонняя реализация на Graph API, не официальный MCP Meta. Требования к типу аккаунта, permissions и App Review зависят от функций. | Только выбранный business/creator аккаунт. На Windows нельзя считать fallback JSON-токены защищённым хранилищем; нужны vault, минимальные scopes и отзыв доступа. |
| [amoCRM API](https://www.amocrm.ru/developers/content/crm_platform/api-reference) и [amoCRM MCP](https://github.com/ivan000vovanov/amocrm-mcp) | Официальный API и сторонний MCP — разные уровни доверия. Универсальный amocrm_request может делать мутации по произвольному API path. | Не переносим широкий токен в агента. Нужен ограниченный адаптер чтения, тестовый аккаунт и отдельное подтверждение записи. StarCRM остаётся вне этой задачи. |
| [Telegram MCP](https://github.com/mcp-telegram/mcp-telegram) | MTProto userbot получает доступ как личный аккаунт, а не как обычный бот уведомлений. | Для уведомлений предпочтителен отдельный бот с разрешёнными чатами. Личную историю и сессию Telegram не подключаем автоматически. |

Число tools — не мера пригодности. Проверка metadata и README не является полным аудитом реализации. В этом проходе ни один из четырёх серверов не установлен и не получил ключи.

### Урок 8. Удалённое управление и юридический чек-лист

[Paseo](https://github.com/getpaseo/paseo) интересен управлением агентами с других устройств, но daemon и плагины получают широкую власть над средой. Для пилота нужны выбранное устройство, отдельная рабочая папка, отзыв доступа и проверка канала связи. Шифрование транспорта не ограничивает полномочия плагина. Автозапуск не включён.

[152-audit](https://152-audit.ru/) — референс интерфейса проверок, не подтверждение соответствия законодательству. Сам сайт оговаривает, что результат не является юридической консультацией. Результаты нельзя выдавать за правовой аудит. Архив по ссылке [Яндекс Диска](https://disk.yandex.ru/d/e2ThqMuXUFZ_rQ) при проверке получить не удалось; содержимое не проверено и не устанавливалось.

## Модуль 5. Skills и инфраструктура Codex

### Урок 9. Повторно не устанавливаем

- [Frontend Design](https://github.com/anthropics/skills/tree/main/skills/frontend-design): подход к визуальному проектированию; локальная копия уже есть. Не заменяет действующий дизайн-системный контракт.
- [Superpowers](https://github.com/obra/superpowers): полезны планирование, воспроизведение ошибок и проверка результата; локальные навыки уже найдены. Это не разрешение создавать ветки, исполнять команды из чужого контента или публиковать код.
- [Find Skills](https://github.com/vercel-labs/skills): поиск пакетов, не аудит доверия. Перед установкой проверяются точная ревизия, лицензия, исполняемые скрипты и сетевые обращения.
- [gstack](https://github.com/garrytan/gstack): изучаем процедуры review; актуальная документация описывает Codex. Автоматический updater, доступ к cookie и deployment не включаем вместе с методическими материалами.

### Урок 10. Экономия контекста не равна экономии всего счёта

[context-mode](https://github.com/mksglu/context-mode) сжимает выдачу инструментов и хранит контекст сессии. Рекламные проценты относятся к конкретному примеру сырого tool output, не к гарантированной экономии всех токенов. Поддержку hook/plugin нужно проверять именно в используемой версии Codex Desktop, а не переносить результат CLI.

Из документации нельзя вслепую исполнять команды, заменяющие AGENTS.md: у нас уже есть правила и границы доступа. История и SQLite-данные нуждаются в правилах хранения. Пилот пока не проводился; установленной и проверенной интеграцией инструмент не считается.

## Модуль 6. Проверяем обещания и фиксируем границы

### Урок 11. Неподтверждённое и устаревшее

[Публикация CL4R1T4S о GPT-6 Astra](https://github.com/elder-plinius/CL4R1T4S/blob/main/OPENAI/Codex_Desktop/GPT-6_Astra_Prompts.md) — сторонний текст. Объём файла и название не подтверждают подлинность внутреннего промпта OpenAI. Это не веса модели. Текст не переносился в активные правила и не использовался для изменения разрешений.

Ссылка [opencode-ai/opencode](https://github.com/opencode-ai/opencode) ведёт в архивированный проект, README указывает перенос в Crush. Этот старый репозиторий не устанавливаем; сохраняем выбранный пользователем Codex.

[Learn Claude Code](https://github.com/shareAI-lab/learn-claude-code) полезен как учебный разбор агентного harness: модель, инструменты, контекст и управление исполнением. Это не обучение собственной базовой модели и не причина активировать Claude Code.

### Урок 12. Приёмка и следующий шаг

Для локального пакета проверяются: три целевых пользовательских сценария, сохранение прежних сцен, безопасная отмена, сброс устаревшего подтверждения, проверки пустых и ошибочных значений, отсутствие внешних запросов, JSON-экспорт и мобильная вёрстка. Сборка сама по себе не доказывает рабочий пользовательский сценарий.

Подключение внешнего инструмента — отдельный этап: выбранный аккаунт → разрешённые данные и методы → закреплённая ревизия → тестовый режим → preview → подтверждение конкретного действия → receipt → отзыв доступа. Пока эти условия не выполнены, статус — **reference / pilot pending**, а не production-ready.

Связанный принцип: [Skills, Connectors & Agent Teams](skills-connectors-and-agent-teams.md). Обновление сайта требует отдельной публикации проверенного пакета; этот гайд не является разрешением на deploy.
