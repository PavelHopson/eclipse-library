# Кинематографическая история с прокруткой: от трёх роликов до браузерного фильма

> Практическое руководство по видео, управляемому прокруткой: драматургия, единая временная шкала, инерционное управление, переходы, звук, доступность, производительность и доказательная проверка качества. Разбираем собственный кейс Eclipse Forge NØRTHBOUND и показываем, как собрать такую историю из трёх видео.

Дата фиксации: **23.08.2026**
Статус: **внедрено как русскоязычный интерактивный кейс на лендинге Eclipse Forge**.

## Короткий вывод

Такой формат нужен не обычной продуктовой странице, а проекту, где само движение является
доказательством компетенции: креативная разработка, премиальный запуск, интерактивный фильм,
портфолио инженера анимации или история бренда. Поэтому решение разделено на два слоя:

- на основном лендинге — лёгкая карточка с постером и понятной меткой `Интерактивный кейс`;
- по клику — отдельная статическая страница, которая загружает видео только после открытия;
- в библиотеке — это руководство, чтобы паттерн можно было воспроизвести на собственных материалах.

Не встраивайте 70–100 МБ видео в главную страницу: это ухудшает скорость первой отрисовки, расходует мобильный трафик и усложняет путь к
основному действию. Интерактивный фильм должен быть осознанным вторым шагом пользователя.

## Права на материалы и честная публикация

В кейсе используются три локальных видео, постеры и шрифты. Права на их использование подтверждены владельцем проекта, а происхождение файлов зафиксировано в отдельном реестре. Публичная страница показывает саму работу Eclipse Forge и не требует от зрителя разбираться в истории подготовки материалов.

Для любого коммерческого проекта до публикации нужны четыре подтверждения:

1. права на видео, музыку, шрифты, постеры и персонажей;
2. разрешение на адаптацию, если повторяется чужая конкретная композиция;
3. реестр происхождения каждого файла и его лицензии;
4. собственные тексты, арт-дирекция и медиаматериалы при превращении учебной работы в клиентский кейс.

## Модуль 1. Когда интерактивный фильм действительно подходит

### Урок 1. Критерий ценности

Формат оправдан, если без движения теряется главный смысл. Хорошие сценарии:

- кинематографический запуск продукта или фильма;
- премиальная история о путешествии, автомобиле или недвижимости;
- интерактивная демонстрация инженерии интерфейса и анимации;
- музейная, музыкальная или модная история;
- эмоциональный кейс, где последовательность важнее быстрого чтения.

Не используйте его для CRM, кабинета оператора, формы бронирования или страницы с частой задачей.
Там пользователь должен действовать, а не ждать режиссёрского темпа.

### Урок 2. Проверка первых трёх секунд

Первый кадр без инструкции обязан объяснить:

- что это за мир;
- что здесь есть движение;
- куда смотреть;
- что делает колесо или свайп;
- как выключить звук и вернуться.

Подсказка `ЛИСТАЙТЕ, ЧТОБЫ НАЧАТЬ` поддерживает очевидную композицию, но не спасает непонятный экран.

## Модуль 2. Драматургия до кода

### Урок 1. Монтажная карта

Сначала посмотрите каждый ролик целиком и выпишите физические события, а не DOM-секции.

| Акт | Событие | Эмоция | Визуальный переход |
|---|---|---|---|
| Departure | двери закрываются, поезд уходит | ожидание → необратимость | бордовый физический wipe |
| Darkness | город исчезает | потеря ориентира | тёплая световая щель |
| Carriage | движение к окну | краткая безопасность | окно поглощает интерьер |
| Whiteout | метель достигает пика | тревога | copy появляется только после удара |
| Passage | вспышки туннеля | лиминальность | текст привязан к свету |
| Aurora | пространство раскрывается | освобождение | никакого большого текста |
| Ice / Water | проход сквозь поверхность | невозможное становится физическим | снег превращается в пузыри |
| Credits | почти неподвижная глубина | послевкусие | титры поверх живого финального кадра |

### Урок 2. Виртуальная длина

Каждому акту назначается длина в `vh`. Это не декоративное число: оно определяет, сколько колесо
прокрутки «времени» отдаёт конкретному событию. В учебном кейсе активная история занимает 1635vh:

```text
departure 220 → intertitle 100 → carriage 210 → intertitle 90
→ whiteout 165 → storm copy 95 → final 580 → credits 175
```

Не делайте все акты одинаковыми. Короткий flash и медленный pullback требуют разной плотности.

## Модуль 3. Архитектура одной сцены

### Урок 1. Закреплённая сцена и невидимая временная шкала

Вместо десятка `position: sticky` используется одна сцена:

```html
<main class="story">
  <div class="cinematic-stage">
    <!-- videos, overlays, text, navigation -->
  </div>
  <div class="timeline">
    <!-- empty sections with CONFIG-driven heights -->
  </div>
</main>
```

```css
.cinematic-stage {
  position: sticky;
  top: 0;
  height: 100svh;
  overflow: clip;
  isolation: isolate;
}

.timeline {
  margin-top: -100svh;
  padding-bottom: 100svh;
}
```

Прокрутка двигается по временной шкале, а один модуль отрисовки получает нормализованный прогресс `0..1` и
управляет всеми слоями. Это убирает рассинхронизацию нескольких компонентов прокрутки.

### Урок 2. Единая конфигурация

Пути, временные точки видео, длины актов, вспышки, главы, интенсивность эффектов и параметры движения должны жить
в одном объекте. Запрещены рассыпанные необъяснимые числа. Минимальная форма:

```js
const CONFIG = {
  videos: {
    departure: { path: "...", start: 0.08, end: 3.78 },
    carriage: { path: "...", interiorEnd: 3.72, stormStart: 3.75, end: 6.65 },
    final: { path: "...", aurora: 13, iceEntry: 30.9, creditsFrame: 35.7 },
  },
  sections: { departure: 220, carriage: 210, final: 580 },
  motion: { scrollLerp: 1.7, seekIntervalMs: 30, seekEpsilon: 0.008 },
};
```

## Модуль 4. Инерция и скраббинг видео

### Урок 1. Один цикл requestAnimationFrame

Обработчик прокрутки обновляет только `targetProgress`. Рендер происходит в одном `requestAnimationFrame`:

```js
current += (target - current) * (1 - Math.exp(-lerpSpeed * deltaSeconds));
render(current);
```

Так движение продолжает мягко затухать после движения колеса мыши и одинаково работает при обратной
прокрутке. Ограничивайте `deltaSeconds` после возврата на вкладку, иначе сцена прыгнет.

### Урок 2. Ограничиваем частоту перемотки

`video.currentTime` — дорогая запись. Обновляйте её только если:

- прошёл минимальный интервал, например 30 мс;
- разница превышает один кадр или заданный порог;
- видео активно или участвует в переходе;
- метаданные уже загружены.

Для длинного финала нужна нелинейная карта времени: туннель можно пройти быстрее, а выход к сиянию и
погружение под лёд — замедлить. Линейный `progress * duration` редко даёт режиссёрский результат.

### Урок 3. Подготовка видео

Для надёжной обратной перемотки:

- используйте локальные файлы и сервер с HTTP Range;
- проверьте частоту ключевых кадров через `ffprobe`;
- не запускайте три видео одновременно;
- предварительно загружайте следующий акт и останавливайте предыдущий;
- при необходимости перекодируйте рабочую копию с частыми ключевыми кадрами, сохранив исходник.

Нельзя ухудшать исходник «ради скорости» без визуального A/B и подтверждения владельца.

## Модуль 5. Переходы, которые ощущаются физически

### Урок 1. Не обычное растворение, а физическая причина

Каждый переход должен вытекать из изображения:

- корпус поезда закрывает кадр → бордовый wipe;
- горизонтальная лампа → light slit → раскрытие вагона;
- окно заполняется снегом → whiteout;
- вспышка туннеля проявляет copy;
- поверхность льда создаёт blur/refraction;
- снежные частицы после погружения становятся пузырями.

Обычное растворение допустимо как запасной вариант, но не как главная режиссура.

### Урок 2. Текст следует монтажу

Текст появляется только после физического события. Например, сообщение о потере связи нельзя показывать в
уютном вагоне до максимальной метели. На сиянии большой текст вообще убирается — кульминационный кадр должен
дышать. Титры разрешены только после фактического достижения позднего подводного кадра, поэтому
проверяется не только scroll progress, но и `video.currentTime`.

## Модуль 6. Motion, звук и доступность

### Урок 1. Звук включается только по выбору пользователя

Сайт всегда стартует с выключенным звуком. AudioContext создаётся или resume только после клика.
Процедурный low-frequency bed дешевле отдельного аудиофайла и может менять mix по сценам:

- rail + low wind на станции;
- тихий drone в вагоне;
- сильнее wind в whiteout;
- свободнее и тише на aurora;
- low-pass и исчезновение rail под водой.

Никакого autoplay громкого звука и резких скачков gain — только ramp / `setTargetAtTime`.

### Урок 2. Режим уменьшенного движения — полноценный маршрут

`prefers-reduced-motion` не означает «показать чёрный экран». Нужен понятный вариант:

- секции сокращаются до 100vh;
- частицы и синхронный seek отключаются;
- выбранные фрагменты проигрываются без звука обычным способом;
- переходы становятся мягким изменением прозрачности около 650 мс;
- все тексты и навигация по главам остаются доступны.

Также нужны видимый фокус клавиатуры, сенсорные цели не меньше 44 пикселей, область голосового объявления главы, ссылка пропуска и запасной текст внутри
`<video>`, `<noscript>` и текстовые подписи к состояниям — не только цвет и движение.

## Модуль 7. Производительность и безопасность

### Урок 1. Требования к производительности

- один RAF;
- пассивные обработчики прокрутки и изменения размера;
- canvas вместо сотен DOM-частиц;
- particle canvas в пониженном разрешении;
- ограничение плотности пикселей на компьютерах и телефонах;
- `will-change` только на реально движущихся слоях;
- не более одного тяжёлого полноэкранного размытия одновременно;
- постер и первый кадр видео доступны до завершения предварительной загрузки;
- пауза видео при `visibilitychange`;
- отдельная страница, чтобы основной лендинг не скачивал видео заранее.

### Урок 2. Требования к безопасности и приватности

Статическая страница всё равно имеет поверхность риска:

- не переносите стороннюю аналитику и баннер бесплатного хостинга из референса;
- все внешние ссылки получают `rel="noopener noreferrer"`;
- никаких ключей, пользовательских данных и хранения в браузере;
- политика безопасности production-сайта разрешает только собственные видео, шрифты и скрипты, если нет обоснованных исключений;
- проверяйте MIME, Range responses, размер и checksum ассетов;
- GSAP должен храниться локально, быть закреплён на конкретной версии и учитываться при проверке зависимостей;
- права на медиаматериалы проверяются отдельно от лицензии JavaScript-библиотеки.

## Модуль 8. Проверка качества как доказательство

### Урок 1. Обязательные контрольные кадры

Снимите эталон и реализацию в одинаковом размере окна и состоянии:

1. paused opening;
2. first intertitle;
3. warm carriage;
4. maximum whiteout;
5. tunnel copy на flash;
6. чистая aurora без headline;
7. exterior pullback;
8. ice entry;
9. underwater credits;
10. mobile opening `390×844`;
11. 4K opening `3840×2160`.

Скриншот сам по себе не QA. Сначала соберите сравнение рядом и контактный лист, затем исправьте отличия
в кадрировании, прозрачности, размере и межбуквенном расстоянии текста, безопасных полях, фильтрах и моменте видео.

### Урок 2. Поведенческая матрица

| Проверка | Компьютер | Телефон | Уменьшенное движение |
|---|---:|---:|---:|
| прокрутка вперёд и назад | ✓ | ✓ | n/a |
| быстрая прокрутка не открывает титры раньше времени | ✓ | ✓ | ✓ |
| звук по умолчанию выключен | ✓ | ✓ | ✓ |
| переход к главе / возврат наверх | ✓ | compact | ✓ |
| нет горизонтального переполнения | ✓ | ✓ | ✓ |
| ошибки в консоли | 0 | 0 | 0 |
| диапазонная загрузка / перемотка видео | ✓ | ✓ | fragment play |
| фокус клавиатуры | ✓ | ✓ | ✓ |

После возврата наверх время видео должно вернуться к первому кадру, а главный экран и подсказка прокрутки — к
исходному состоянию. Проверьте это отдельно, а не считайте автоматическим следствием progress `0`.

## Как применить паттерн в проектах Eclipse

- **Eclipse Forge Landing:** только entry-card и отдельный case route.
- **Premium Rent:** кинематографический launch конкретного автомобиля, но не booking flow.
- **Shotforge:** обучающий case о переходе storyboard → final render.
- **Eclipse Media:** showcase media pipeline, не основной downloader UI.
- **Agent Office:** не применять к dashboard; допустим только отдельный launch-film продукта.

## Критерии готовности

- история понятна без инструкции и без звука;
- права на все видео, шрифты и изображения подтверждены;
- видео локальны и не загружаются с главной страницы;
- первый кадр точный и не прыгает при старте;
- обратная прокрутка не ломает видео и тексты;
- титры появляются только в нужный момент видео;
- на телефоне нет переполнения и сохраняется живой видеоэкран;
- маршрут с уменьшенным движением завершён;
- все видимые элементы управления работают;
- сравнение макета с контрольными кадрами и проверка консоли зафиксированы;
- основной лендинг проходит прежние проверки сборки, тестов и размера файлов.
