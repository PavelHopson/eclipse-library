Практический гайд по интерактивному Canvas-постеру: два прозрачных портрета, курсор-слизь, раскрытие костюма и восстановление одним нажатием. Без библиотек и фреймворков.

Этот материал объединяет полный бриф пользователя из «Gwen Stacy.docx» и инженерный разбор реализации. Оригинальный текст сохранён отдельно, без скрытого превращения промпта в правила Codex. Дата подготовки: 5 сентября 2026 года.

Формат: десктопный фан-концепт, один экран без прокрутки. Стек: HTML, CSS, vanilla JavaScript и Canvas 2D. Результат: управляемое раскрытие лица, молочный след на стене, кнопки восстановления, ручного раскрытия и остановки движения.

Локальный проект лежит в web/experiments/gwen-reveal/. Откройте его из ссылки «Gwen: по ту сторону маски» в Animation Lab. Иллюстрированная версия гайда находится рядом со сценой в guide.html; в ней есть исходный бриф и оформленный DOCX. Это локальная реализация, не заявление о публикации.

Модуль 1. От идеи к проверяемому результату

Урок 1. Что делает эффект понятным

Внешний слой показывает костюм. Внутренний слой показывает портрет. Капля не меняет изображение и не генерирует лицо: она временно делает часть внешнего слоя прозрачной. На чёрной стене та же маска превращается в молочную субстанцию. Один жест управляет двумя согласованными эффектами.

Главное действие доступно без чтения документа: курсор подводит к маске, начальная демонстрация показывает результат, кнопка «Снять маску» даёт альтернативу мыши, а «Восстановить» возвращает исходный кадр. Демонстрация длится четыре секунды и прекращается при первом движении пользователя.

Урок 2. Что нужно подготовить

  • Два PNG одинакового размера и с общей системой координат.
  • Реальный альфа-канал, а не чёрный фон, нарисованный вокруг персонажа.
  • Понятный основной экран, без прокрутки и дополнительных страниц внутри сцены.
  • Отдельный режим с уменьшенным движением и работающие кнопки для клавиатуры.
  • Зафиксированные права на изображения перед публичным распространением.

В предоставленных файлах Suit.png и Sadie.png действительно есть прозрачность. Оба имеют размер 1360×768. Белые поля и чёрный фон в некоторых просмотрщиках не доказывают отсутствие альфа-канала. Проверять нужно данные файла, а не цвет превью.

Модуль 2. Ассеты без потери совмещения

Урок 3. Один бокс для двух изображений

Сначала объединяем альфа-каналы, затем вычисляем общий bounding box. Добавляем 24 пикселя с каждой стороны. Обрезаем оба изображения одним и тем же боксом. Только после этого масштабируем их до ширины 1400 пикселей.

Для этой пары общий бокс с запасом: (247, 5, 1130, 792). Нижний запас выходит за исходный кадр и заполняется прозрачностью. Итоговый размер: 1400×1248. Высота 1230 из примерной CSS-формулы брифа не подменяет фактическую геометрию изображения.

union = ImageChops.lighter(suit.getchannel('A'), face.getchannel('A'))
x0, y0, x1, y1 = union.getbbox()
box = (x0 - 24, y0 - 24, x1 + 24, y1 + 24)
size = (1400, round(1400 * (box[3]-box[1]) / (box[2]-box[0])))
suit = suit.crop(box).resize(size, Image.Resampling.LANCZOS)
face = face.crop(box).resize(size, Image.Resampling.LANCZOS)

Не обрезайте портреты независимо. Даже небольшой разный сдвиг заметен при раскрытии глаз. В этом проекте не используется генеративная замена лица или геометрическая деформация портрета. Проверка совмещения остаётся визуальным пунктом приёмки.

Урок 4. Matte для стены

Из объединения альфа-каналов делаем маску силуэта. MaxFilter(11) расширяет край примерно на 5 пикселей, GaussianBlur(3) сглаживает переход. Цвет PNG может быть белым: для destination-out важна прозрачность, а не RGB.

alpha = ImageChops.lighter(suit.getchannel('A'), face.getchannel('A'))
alpha = alpha.filter(ImageFilter.MaxFilter(11))
alpha = alpha.filter(ImageFilter.GaussianBlur(3))

Матте не заменяет маску костюма. Внутренний портрет обрезается альфой костюма; молочная слизь на стене стирается более широким matte. Это не даёт белой субстанции закрыть героиню.

Результаты подготовки: suit.webp, face.webp, matte.png. WebP сохраняются с quality 90. provenance.json содержит размеры, общий crop и SHA-256 оригиналов. Оригинальные PNG не изменяются.

Модуль 3. Композиция и слои

Урок 5. Порядок важнее количества z-index

Нельзя случайно создать stacking context у обёртки героини через transform, opacity, filter или собственный z-index. Перемещение самого canvas внутри обёртки не должно поднимать весь контейнер над интерфейсом. В мобильном упрощённом режиме композиция проверяется отдельно.

Урок 6. Чёрная стена и стикеры

Палитра сохраняет бриф: #08080A, #F6F2FF, #FF2D87, #22E0FF. Основная типографика использует Inter Tight. Латинская UI-обвязка использует Chakra Petch; для русских букв нужен кириллический fallback, поскольку выбранный Chakra Petch не содержит кириллицу. Шрифты и OFL-лицензии лежат в проекте локально.

GWEN нарисован четырьмя непрерывными ломаными path. Несколько use переиспользуют геометрию для призрачных дублей. Сплошные серые цвета позволяют буквам закрывать паутину. Срезанные углы интерфейса задаёт clip-path, а не случайные радиусы карточек.

Гличи и параллакс не должны конкурировать с основным действием. При reduced motion или ручной паузе они выключаются. Кнопка «Смотреть эффект» запускает реальную демонстрацию Canvas, а не обещает отсутствующий видеотрейлер. Галерея открывает два предоставленных кадра. Музыка не подключается без исходного файла и понятных прав.

Модуль 4. Физика молочной капли

Урок 7. След, узлы и независимость от FPS

Четыре масочных буфера работают в масштабе 0.55 от экрана: trail, goo, ring, gloss. Дополнительные буферы нужны для готового внутреннего портрета, костюма и стенового слоя. Это Canvas-рендер, а не обещание «только transform и opacity».

Голова цепочки тянется к указателю с коэффициентом 0.42, следующие восемь узлов тянутся к предыдущему с 0.34. Размер сужается до 38% у хвоста. Базовый радиус равен 6.2% меньшей стороны экрана с ограничением 26-62 px. При зажатой кнопке радиус плавно увеличивается в 1.45 раза.

const frameK = (base, dt) => 1 - Math.pow(1 - base, dt / (1000 / 60));
node.x += (target.x - node.x) * frameK(0.42, dt);
node.y += (target.y - node.y) * frameK(0.42, dt);

Та же нормализация применяется к затуханию 3.2%, изменению целостности и физике подтёков. После переключения вкладки время кадра сбрасывается: симуляция не догоняет минуты отсутствия огромным скачком.

Между старой и новой позицией узла ставятся промежуточные штампы с шагом примерно r/3. Это сохраняет непрерывность на быстрой мыши. Три сателлита вокруг штампа делают край неровным; ограниченное число подтёков не позволяет массиву расти бесконечно.

Урок 8. Слипание, блик и раскрытие

goo получает размытую версию следа и порог альфа-канала через SVG feColorMatrix. Поддержка фильтра проверяется при запуске: непрозрачный центр, прозрачная внешняя область и исчезновение слабого контрольного пятна. Последняя проверка отличает работающий фильтр от браузера, который тихо проигнорировал url(#...).

При неподдерживаемом фильтре используется blur(6px). Такой fallback мягче настоящего metaball-порога; это честное визуальное отличие, а не идентичный результат. Кайма строится как размытие goo минус goo, блик как разность двух слегка сдвинутых копий.

face -> destination-in(suit alpha) -> внутренний портрет
suit -> destination-out(goo) -> костюм с отверстием
внутренний портрет + костюм + край -> canvas героини
молочное goo + кайма + блик -> destination-out(matte) -> стена

Все экранные координаты переводятся в координаты canvas через сохранённый прямоугольник героини. Он пересчитывается при resize, не на каждом кадре. Буфер героини ограничен шириной 1600 px, devicePixelRatio ограничен 2.

Модуль 5. Приёмка без самообмана

Урок 9. Доступность и состояния

  • Loading: статичный постер остаётся видимым, действия раскрытия выключены до загрузки всех масок.
  • Error: понятное сообщение, сохранённый постер, обычный курсор, никакого бесконечного спиннера.
  • Empty: отсутствие обязательного изображения считается ошибкой входа, не пустым чёрным экраном.
  • Success: маска открывается, а восстановление немедленно возвращает целостность 100%.
  • Keyboard: Tab, Enter, Escape, заметный фокус и модальный диалог с возвратом фокуса.
  • Reduced motion: отключены автопилот, инерционный хвост, гличи и параллакс; ручное раскрытие остаётся доступным.
  • Mobile: упрощённый портрет с кнопками; десктопная навигация и боковой постер не сдавливаются в узкую колонку.
  • Hidden tab: кадры не продолжают тратить ресурсы, зажатая кнопка сбрасывается при потере фокуса.

Целостность обновляется в DOM не чаще раза в 90 ms. Изменение процентов не озвучивается скринридером каждый кадр: озвучиваются только осмысленные события, например завершение восстановления.

В DevTools доступна функция gwenDiagnostics(): режим фильтра, число кадров, размер canvas, усреднённое время рендера и недавний FPS. Это диагностический снимок, не инструмент записи пользовательских действий. Значение 60 FPS нельзя обещать по одному только размеру буферов. Проверяйте целевое железо, нагрузку GPU и конкретный браузер; измерения и ограничения фиксируются в design-qa.md проекта.

Модуль 6. Где использовать и как публиковать

Урок 11. Применение в Eclipse

Animation Lab: самостоятельный арт-эксперимент и практический гайд. Не смешиваем fan-concept с production-компонентами форм или оплат.

Eclipse Forge: демонстрация качества интерактивной разработки в портфолио. В кейсе полезнее показать курсор, раскрытие и восстановление, чем разместить один статичный скриншот.

Eclipse Media: тот же технический приём подходит для просмотра «до/после» цветокоррекции, ретуши или монтажа. Для рабочего инструмента лучше заменить декоративную слизь предсказуемой маской/ползунком и сохранить нейтральный интерфейс.

Цифровой компаньон: эффект можно использовать для смены состояния собственного аватара. Он не доказывает наличия 3D-модели, распознавания эмоций или realtime lip-sync. Нужны свои права на персонажа и портрет.

Урок 12. Публикация отдельным решением

Сначала локальная проверка и review прав на исходники. Затем можно разместить проверенную статическую папку в библиотеке. Для независимого демо подходят GitHub Pages и Cloudflare Pages: обе платформы поддерживают статические HTML/CSS/JS-проекты.

Публичный репозиторий или хостинг не создаётся автоматически этим гайдом. noindex снижает случайную индексацию концепта, но не является контролем доступа. Если материалы должны оставаться приватными, нужен закрытый preview, а не одна мета-строка.

Перед коммерческим использованием замените персонажа и портрет на собственные или лицензированные материалы. Не называйте фан-концепт официальным проектом Marvel, не выдавайте предоставление файла за разрешение на любое распространение и не переносите OFL-лицензию шрифтов на изображения.

Приложение. Полный авторский бриф и исходники

Полный текст из предоставленного Gwen Stacy.docx сохранён в assets/original-brief.txt рядом с проектом. Он включён в иллюстрированную HTML-версию и в приложение оформленного DOCX. Порядок пунктов и технические значения сохранены. Дополнения реализации описаны выше отдельно: фактическая высота 1248 px, русские подписи, рабочая демонстрация вместо отсутствующего трейлера, обработка ошибок и клавиатурный режим.

Подготовка ассетов выполняется локальным скриптом scripts/prepare-gwen-assets.py, оформление гайда и DOCX скриптом scripts/build-gwen-guide.py. Runtime самого эффекта состоит из трёх файлов. HTML-версия гайда, документ, provenance и инструменты сборки являются сопровождающими материалами, а не зависимостями сцены.

- зерно: SVG feTurbulence (baseFrequency .85), mix-blend-mode:soft-light, opacity .2.

ГРАФФИТИ-ТЕГ «GWEN» (не шрифт! рисованный SVG-wildstyle)
- инлайн-SVG viewBox ~1160×430; каждая буква — ОДИН непрерывный ломаный path;
- стиль штриха: stroke-width 36, stroke-linecap square, stroke-linejoin miter,
stroke-miterlimit 14, fill none;
- геометрия: у букв шипы-засечки на концах; наклоны согласованы — верхние перекладины
идут вверх-вправо, стойки чуть завалены вправо, диагонали W и N параллельны, первый и
последний штрихи W зеркальны; G с открытым просветом и перекладиной внутрь (не Q!);
буквы разделены зазорами; под словом — росчерк на всю ширину с «галочкой» на конце;
вокруг — 6 мелких косых параллелограммов-обломков;
- слои через <defs>+<use> (4 шт.): два призрачных дубля #26262B и #1F1F23, поверх —
ядро #5A5960; цвета СПЛОШНЫЕ, не rgba — тег должен перекрывать паутину, а не
просвечивать её;
- гличи: дубли дёргаются через steps(1) — циклы 2.1s и 2.7s, 5–6 ключевых кадров со
сдвигами от −21 до +19px; раз в 4.2s весь SVG коротко дёргается двумя кадрами
translate+skewX(±2–2.5°);
- посадка: rotate(−3°), строго по центру экрана — проверь фактический bbox рисунка и
сдвинь viewBox так, чтобы визуальный центр совпал с геометрическим;
- параллакс: тег плавно уезжает от курсора (цель: (0.5−x/W)×26px, (0.5−y/H)×14px,
lerp ~0.06/кадр), наклон −3° сохраняется в transform.

ГЕРОИНЯ
Канвас по центру, во весь экран по высоте: width:min(118vw, 100dvh×(1400/1230)).
Рендер в разрешении экрана: ширина = min(1600, max(600, cssWidth×min(dpr,2))).
Композиция каждый кадр:
1) face → drawImage;
2) face обрезать силуэтом костюма: destination-in по suit (чтобы из-под капюшона не
торчал второй кадр);
3) сверху suit, из которого вырезаны дыры каплей: destination-out по goo-маске
(пересчёт координат экран→канвас);
4) по краю разрыва: тень (goo blur 6px, alpha .5, source-atop) и призрачно-белая кайма
(alpha .9).
Появление: opacity 0→1 за 0.9s после загрузки всех трёх картинок.

КУРСОР-СЛИЗЬ (главный эффект)
cursor:none на body. Offscreen-канвасы в масштабе 0.55 от экрана: trail, goo, ring, gloss.
1) След: пятна копятся в trail и тают через destination-out ~3.2%/кадр (нормируй на dt).
2) Капля — пружинная цепочка из 9 узлов: узел 0 тянется к курсору (lerp .42/кадр),
каждый следующий — к предыдущему (.34), радиусы убывают до 38%. Базовый радиус
6.2% меньшей стороны экрана (клемп 26–62px), при зажатой кнопке ×1.45 (lerp .14).
Все коэффициенты frame-rate-независимы: k = 1−(1−base)^(dt/16.67).
3) Между позициями узла за кадр — «мазок»: промежуточные штампы через каждые ~r/3,
чтобы след не рвался на быстрой мыши.
4) Неровный край: у каждого штампа 3 пятна-сателлита (радиус ~50%, дрейф по синусоидам
от времени и seed).
5) Подтёки: раз в 240–860ms из хвоста падает капля (vy += 0.075/кадр, радиус ×0.986,
удалить при r<2.5 или за экраном).
6) Слипание (metaball): goo = trail через SVG-фильтр feGaussianBlur stdDeviation 7 +
feColorMatrix (alpha: ×24, −12). ОБЯЗАТЕЛЬНО runtime-тест: нарисуй круг на тестовом
канвасе с ctx.filter='url(#goo)', проверь getImageData (в центре alpha>200, снаружи
<40); если не работает — фолбэк blur(6px).
7) Кайма: blur(5px) от goo минус сам goo (destination-out), закрашено градиентом
#F6F2FF→#D9D2EC→#F6F2FF.
Блик: goo минус goo со сдвигом (−3,−4), source-in rgba(226,210,255,.9).
9) Полноэкранный слой слизи: кайма-свечение (alpha .75) → goo → тело молочным #EFEBF8
(source-atop, alpha .9) → лавандовый градиент-перелив (alpha .18) → блик (blur 2px,
alpha .62) → destination-out по matte.png в позиции героини (слизь живёт на стене,
но обтекает силуэт).
10) Автопилот: пока мышь не двигалась (и первые ~4s), капля сама водит по лицу по
синусоидам; первый pointermove отключает его и прячет подсказку.
