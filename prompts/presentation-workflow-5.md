# Презентация: проверяемый workflow из 5 промптов

Набор помогает пройти путь от идеи до HTML/PDF-презентации. Он не гарантирует продажи и не заменяет проверку фактов, дизайна и экспортированного файла человеком.

## Перед началом

Подготовьте: тему, цель, аудиторию, продукт, одно главное действие, подтверждённые факты, ссылки на источники, бренд-цвета и ограничения. Не передавайте модели закрытые данные клиентов, пароли или материалы без права на использование.

## 1. Логика презентации

```text
Ты — редактор продуктовых презентаций. Создай структуру презентации на тему [ТЕМА].

Цель: [ОБЪЯСНИТЬ / ПРОДАТЬ / ПОЛУЧИТЬ СОГЛАСОВАНИЕ].
Аудитория: [КТО И ЧТО УЖЕ ЗНАЕТ].
Продукт или идея: [ОПИСАНИЕ].
Главное действие после просмотра: [CTA].
Подтверждённые факты и источники: [СПИСОК].
Что нельзя утверждать: [ОГРАНИЧЕНИЯ].

Предложи 8–12 слайдов. Для каждого укажи:
1) заголовок; 2) один главный тезис; 3) доказательство или источник;
4) зачем слайд нужен; 5) вывод для зрителя; 6) подходящий визуальный формат.

Не придумывай цифры, клиентов, отзывы и результаты. Неподтверждённое помечай «нужно проверить».
```

## 2. Текст для слайдов

```text
На основе согласованной структуры напиши текст слайдов для аудитории [АУДИТОРИЯ].
Тон: [ТОН БРЕНДА]. На слайде — один тезис, короткий заголовок и не более 35 слов основного текста.
Отдельно дай заметки спикера. Каждую цифру сопровождай ссылкой на источник или меткой «нужно проверить».
Покажи переход от проблемы к решению, доказательствам, ограничениям и следующему действию.
Не используй давление, ложную срочность и неподтверждённые превосходные степени.
```

## 3. HTML-презентация

```text
Преобразуй согласованный текст в один автономный HTML-файл с CSS.
Формат слайда 16:9; печать — один слайд на страницу; без внешних scripts и analytics.
Используй семантическую разметку, системные или локальные шрифты, видимый focus и достаточный contrast.
Поддержи 1920×1080, ноутбук и мобильный preview. Уважай prefers-reduced-motion; анимации не обязательны.
Цвета: [ЦВЕТА]. Стиль: [СТИЛЬ]. Изображения используй только с указанной лицензией и alt-текстом.
Верни полный HTML и короткий список мест, которые требуют ручной проверки.
```

## 4. Визуальная система и редактура

```text
Проведи дизайн-review HTML-презентации. Проверь визуальную иерархию, плотность, типографику,
отступы, контраст, единообразие компонентов, читаемость графиков и заметность CTA.

Сначала перечисли проблемы по приоритету P0–P3 и объясни влияние на зрителя.
Затем предложи минимальный diff, который исправляет проблемы без декоративной перегрузки.
Не скрывай ограничения продукта и не превращай каждый блок в карточку.
```

## 5. Проверка PDF

```text
Проверь HTML перед экспортом в PDF: print CSS, размер 16:9, page-break, переполнение,
обрезанные элементы, переносы, встроенные изображения, ссылки, контраст и номера страниц.
Составь короткий checklist для ручного просмотра каждого экспортированного слайда.
Не утверждай, что PDF готов, если файл не был реально открыт и визуально проверен.
```

## Критерий готовности

Презентация готова только после проверки фактов, лицензий на визуальные материалы, desktop/mobile preview и визуального просмотра итогового PDF.
